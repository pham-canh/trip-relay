# Spec mapping

This maps Trip Relay to the Open Agentic Web Challenge MVP Profile 0.2. "Caller" means Skyline Air (`site/`); "peer" means Harbor Hotel (`peer/`). The interaction pattern and its limits are described in [PROTOCOL.md](../PROTOCOL.md).

## Minimum public files

| Requirement | Where | Evidence |
| --- | --- | --- |
| `agent-manifest.json` with network, front man, HOCON, router, peer policy | `site/agent-manifest.json`, `peer/agent-manifest.json` | Both manifests validate at boot; `npm test` reads them directly. |
| Resolved network JSON | `site/skyline_air.network.json`, `peer/harbor_hotel.network.json` | Built from HOCON with the Agentify skill, which parses with the same runtime that loads it. |
| `links.json` | `site/links.json`, `peer/links.json` | Published link maps, with the concrete hotel URL in the caller's HOCON. |
| CORS on public artifacts | GitHub Pages and `scripts/serve.mjs` | GitHub Pages sends `Access-Control-Allow-Origin: *`; the local server does the same on every response. The browser test fetches the peer manifest from the caller origin. |
| Optional discovery metadata | `.well-known/nsdeploy.json`, `.well-known/nsdeploy-agent.json` | Generated by the build and committed. |
| Internal agent plus a grounded capability | Caller network | Front agent delegates to `fare_agent`; both use `website_get_airline_state`, `website_select_flight`, `website_book_flight` from the page. |

## Browser execution and composition

| Requirement | Where | Evidence |
| --- | --- | --- |
| Runtime runs the graph in JavaScript in a normal page | `site/runtime/`, `peer/runtime/` | Boot happens in `site.js` / `peer/site.js`; the Playwright pass boots both pages with no console errors. |
| Validation gates execution | runtime `kernel.js` | Both networks pass `validateNetwork`; the caller test asserts no errors. |
| Writes show destination and arguments; irreversible actions confirm | `site/site.js`, `peer/site.js` | `DIALOGS.book_flight` says “Book this flight?”; `DIALOGS.request_room` says “Start this room request?”. `confirmWebsiteActions` is absent in the unit test without a handler, so the tool is not offered. |
| Stale or invalid writes are refused | `site/app.js`, `peer/app.js` | `expectedVersion` check; tests cover a stale version, an unknown flight id, an unknown room type, and a blank passenger name. |
| Peer manifest is loaded only after consent | runtime `engine.js`, `ui.js` | Browser test records zero requests to the peer origin before **Allow**, then sees `/agent-manifest.json` after. Local evidence: `localhost:8081`; hosted evidence: `pham-canh.github.io.`. |
| Consent names origin, purpose, request | `runtime/ui.js` consent card | Card shows the peer origin (`localhost:8081` locally; `pham-canh.github.io.` hosted), a token estimate, and the exact request text. |
| Exact named network, no fallback | runtime `engine.js` | The link is the exact `http://localhost:8081/harbor_hotel` locally and `https://pham-canh.github.io./harbor_hotel` hosted; the peer manifest is read at the declared base. |
| Private context is not forwarded | runtime `engine.js` | The hotel receives only the `request` string; the runtime does not forward caller history, page state, the airline passenger record, the fare selection, or the key. |
| Peer cannot receive or change the caller's key/router | runtime `engine.js` | Peer compile uses `selectPeerRouter(this.userRouter)` and runs locally; no key is sent to the hotel origin. |
| Protected values are blocked at every egress | runtime `dlp.js`, `runner.js` | Peer request, `sly_data`, coded-tool args, MCP args, presentation, and peer output are scanned; `npm run benchmark:dlp` reports 12/12 attacks blocked with 0 canary egress. The browser pass also blocks an outbound email and an inbound API key with a hostile peer fixture. |
| Consent approval is scoped | runtime `engine.js` | **Always allow** is bound to origin + kind + phase + request hash and expires after five minutes; a different request asks again. |
| Audit is tamper-evident within the tab | runtime `audit.js`, `audit-store.js`, page **Privacy receipt** | Hash-chained events, redaction before hashing, in-page verify and JSON download; the redacted chain is stored in this tab's IndexedDB and restored after a reload. A tampered stored chain is refused. `npm run benchmark:dlp` checks tamper detection. Not a remote WORM store. |
| Peer failure is observable | runtime `remote.js`, `engine.js`, page **Privacy receipt** | An 8-second timeout and HTTP/JSON/CORS failures return an actionable error and append a redacted `peer_error` receipt event. |
| Peer policy is closed and explicit | both manifests | Caller allows only the hotel origin (`http://localhost:8081` locally; `https://pham-canh.github.io.` hosted); hotel allows none. A denied origin fails closed. |
| Observable execution | runtime trace and **Developer** toggle | Router host, tool calls, origins, and receipt status are visible in the UI. |

## Pluggable inference

| Requirement | Where | Evidence |
| --- | --- | --- |
| Published default router | both manifests | `https://api.otari.ai/api/v1`, model `alibaba/qwen-3.5-35b-a3b`. EU keys use the settings preset at `https://eu.api.otari.ai/api/v1`. |
| BYOK selection of router and model | runtime settings panel | Includes **Otari (Mozilla)** and **Otari (Mozilla, EU)** presets plus free-form router/model fields. |
| Key stays out of URLs and artifacts | runtime `byok.js`, `llm.js` | Key is read from browser storage and sent only as `Authorization` to the selected router; manifests and network JSON contain no key. |
| Missing key stops the model call | runtime `llm.js` | The status line asks for a key; the page remains usable without one. |
| Peer runs with the caller's inference path | runtime `engine.js` | The hotel network is compiled with the caller's router; it cannot supply its own. |

## Security and privacy

- **Untrusted peer definitions:** the hotel's HOCON and instructions are treated as data for the model; it cannot execute undeclared code, and this demo ships no coded-tool bundle.
- **Explicit destinations:** consent appears before any third-party contact, and the request text is shown, not just the host.
- **Private context by exception:** only the natural-language `request` crosses the boundary.
- **DLP at the boundary:** a canary, email, API key, or bearer token is blocked before peer egress, coded-tool execution, `sly_data`, or peer output is rendered.
- **Per-tab audit, not remote attestation:** the hash-chained log proves tamper evidence within the tab and survives a reload in IndexedDB, but the browser profile can delete it; a production system still needs a remote sink.
- **Unknown outcome:** the runtime reports cancelled/unknown tool results; the agent is instructed not to retry a write with an unknown outcome.
- **Demo data:** no real passenger data, no payment details, no server-side state, and no calls to real airline or hotel systems.

## Official tooling check

On 2026-11-28, the challenge's own [`check_partner.mjs`](https://github.com/cognizant-ai-labs/agentic-web/blob/main/skills/agentify-website/scripts/check_partner.mjs) returned `OK` for the hosted pair in both directions. It read the manifest, network, `links.json`, bridge page, bridge script, and bridge manifest with a caller `Origin`; every file answered 200 with CORS; the hotel shares no actions with the caller; the airline's `allowed_peers` matches the hotel origin.

```bash
node skills/agentify-website/scripts/check_partner.mjs \
  https://pham-canh.github.io./harbor_hotel \
  --origin https://pham-canh.github.io

node skills/agentify-website/scripts/check_partner.mjs \
  https://pham-canh.github.io/trip-relay/skyline_air \
  --origin https://pham-canh.github.io.
```

## Not implemented

These are optional in the MVP and intentionally out of scope for this demo:

- A public MCP facade (`agent_mcp.available: false`).
- Coded-tool bundles and Web Worker isolation.
- An A2A agent card.
- A production deployment behind a real travel inventory, payments, or authentication. The public demo is static and uses generated flights and request-only rooms.
