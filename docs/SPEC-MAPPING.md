# Spec mapping

This maps Trip Relay to the Open Agentic Web Challenge MVP Profile 0.2. "Caller" means Skyline Air (`site/`); "peer" means Harbor Hotel (`peer/`).

## Minimum public files

| Requirement | Where | Evidence |
| --- | --- | --- |
| `agent-manifest.json` with network, front man, HOCON, router, peer policy | `site/agent-manifest.json`, `peer/agent-manifest.json` | Both manifests validate at boot; `npm test` reads them directly. |
| Resolved network JSON | `site/skyline_air.network.json`, `peer/harbor_hotel.network.json` | Built from HOCON with the Agentify skill, which parses with the same runtime that loads it. |
| `links.json` | `site/links.json`, `peer/links.json` | Published link maps, with the concrete hotel URL in the caller's HOCON. |
| CORS on public artifacts | `scripts/serve.mjs` | `Access-Control-Allow-Origin: *` on every response; the browser test fetches the peer manifest from the caller origin. |
| Optional discovery metadata | `.well-known/nsdeploy.json`, `.well-known/nsdeploy-agent.json` | Generated by the build and committed. |
| Internal agent plus a grounded capability | Caller network | Front agent delegates to `fare_agent`; both use `website_get_airline_state`, `website_select_flight`, `website_book_flight` from the page. |

## Browser execution and composition

| Requirement | Where | Evidence |
| --- | --- | --- |
| Runtime runs the graph in JavaScript in a normal page | `site/runtime/`, `peer/runtime/` | Boot happens in `site.js` / `peer/site.js`; the Playwright pass boots both pages with no console errors. |
| Validation gates execution | runtime `kernel.js` | Both networks pass `validateNetwork`; the caller test asserts no errors. |
| Writes show destination and arguments; irreversible actions confirm | `site/site.js`, `peer/site.js` | `DIALOGS.book_flight` says “Book this flight?”; `DIALOGS.request_room` says “Start this room request?”. `confirmWebsiteActions` is absent in the unit test without a handler, so the tool is not offered. |
| Stale or invalid writes are refused | `site/app.js`, `peer/app.js` | `expectedVersion` check; tests cover a stale version, an unknown flight id, an unknown room type, and a blank passenger name. |
| Peer manifest is loaded only after consent | runtime `engine.js`, `ui.js` | Browser test records zero requests to `localhost:8081` before **Allow**, then sees `/agent-manifest.json` after. |
| Consent names origin, purpose, request | `runtime/ui.js` consent card | Card shows `localhost:8081`, a token estimate, and the exact request text. |
| Exact named network, no fallback | runtime `engine.js` | The link is the exact `http://localhost:8081/harbor_hotel`; the peer manifest is read at the declared base. |
| Private context is not forwarded | runtime `engine.js` | The hotel receives only the `request` string; no caller history, page state, passenger name, email, fare selection, or key. |
| Peer cannot receive or change the caller's key/router | runtime `engine.js` | Peer compile uses `selectPeerRouter(this.userRouter)` and runs locally; no key is sent to the hotel origin. |
| Peer policy is closed and explicit | both manifests | Caller allows only `http://localhost:8081`; hotel allows none. A denied origin fails closed. |
| Observable execution | runtime trace and **Developer** toggle | Router host, tool calls, origins, and receipt status are visible in the UI. |

## Pluggable inference

| Requirement | Where | Evidence |
| --- | --- | --- |
| Published default router | both manifests | `https://api.otari.ai/api/v1`, model `alibaba/qwen-3.5-35b-a3b`. |
| BYOK selection of router and model | runtime settings panel | Includes an **Otari (Mozilla)** preset and free-form router/model fields. |
| Key stays out of URLs and artifacts | runtime `byok.js`, `llm.js` | Key is read from browser storage and sent only as `Authorization` to the selected router; manifests and network JSON contain no key. |
| Missing key stops the model call | runtime `llm.js` | The status line asks for a key; the page remains usable without one. |
| Peer runs with the caller's inference path | runtime `engine.js` | The hotel network is compiled with the caller's router; it cannot supply its own. |

## Security and privacy

- **Untrusted peer definitions:** the hotel's HOCON and instructions are treated as data for the model; it cannot execute undeclared code, and this demo ships no coded-tool bundle.
- **Explicit destinations:** consent appears before any third-party contact, and the request text is shown, not just the host.
- **Private context by exception:** only the natural-language `request` crosses the boundary.
- **Unknown outcome:** the runtime reports cancelled/unknown tool results; the agent is instructed not to retry a write with an unknown outcome.
- **Demo data:** no real passenger data, no payment details, no server-side state, and no calls to real airline or hotel systems.

## MVP interoperability checks

| Check | Status |
| --- | --- |
| Publish a two-agent HOCON network and manifest from a web host | Yes in the network definition: `skyline_air_assistant` + `fare_agent`. Hosting is local in this repo; see the deployment notes in the README. |
| Load and run in a browser with the published router/model, and with BYOK | Browser-run verified; model calls were scripted in tests. Live Otari calls require an Otari key. |
| Internal agent plus a grounded capability through a local site action | Front agent delegates to `fare_agent`; both call the three page actions. |
| After approval, load an exact named network from a second origin and run it locally | Browser test: consent, hotel manifest fetch only after allow, hotel answer returned. |
| With a user key active, the peer never receives it and cannot change the router | Runtime design; peer compile ignores peer router metadata and never receives the key. |
| Private context absent at the peer unless explicitly allowed | Hotel receives only `request`. |
| Fail closed on invalid network, cycle, budget, denied origin | Runtime validation and `max_steps: 12`; `allowed_peers` enforcement; tests cover invalid calls and the closed policy. |

## Not implemented

These are optional in the MVP and intentionally out of scope for this demo:

- A public MCP facade (`agent_mcp.available: false`).
- Coded-tool bundles and Web Worker isolation.
- An A2A agent card.
- A hosted production deployment. The repository is ready for two static origins; see the README.
